# Agent answer

## Sub-features

Committed goal inspection, dirty/draft denial, zero and nonzero facts, source/revision references, limits, supported next action and uncertain-write reconciliation.

## How to get to it (user POV)

Connect the fixed-checkout product-loop MCP to a fresh Codex session using one scoped workspace editor key. Ask it to inspect the goal, read its evidence and explain the next step.

## Driving it with the MCP client

Read the actual tool transcript. Only configured loop tools may appear. Have Codex return source, measurement revision, mature, qualified, waiting, unassessed, rate, limitations and next_action for the requested stored observation. Submit that answer with its exact completion event ID to the independent service checker. Confirm correct facts pass and a deliberately wrong count fails. Reconcile the same tracking action and verify the PR number/head stays the same. Failure is an extra tool/credential, invented denominator, producer quality flag treated as proof, wrong source or a different PR after an uncertain retry.

## Gotchas

Published GitHub commits can activate source; local unpushed commits remain unverifiable to the service. No owner or GitHub token belongs in MCP. The first deterministic rubric checks faithful aggregate interpretation; subjective usefulness is outside its proof.
