MIT open-source analytics. Self-hosting is the default, with no billing account or commercial event/project/seat quotas. Operational query and retention bounds still apply. Every example below targets your own deployment.

Choose the narrowest connection

Account sessions follow verified email login. Workspace keys delegate one workspace role. Editors configure projects; owners manage access. Aggregate read keys serve one project; audit-purpose keys can read only the approved diagnostic catalog, review and trace. Producer write keys cannot read analytics. Keep credentials out of command arguments, chat, URLs and browser bundles.

For the built-in Codex journey, POST connection with an empty body when setup begins. Reconnect returns the original workspace clock. The service environment must match the goal mapping.

The first rubric checks a structured answer against trusted stored aggregate facts. Producer quality flags are ignored. One workspace has one first-entry clock and a full 24-hour follow-up. Mature, waiting, failed, unassessed and timed-out counts stay separate. Before/after is observational. External attestations never silently enter the native denominator. Scans and artifact preparation return HTTP202 while pending. Poll the returned status path. Retry failed or interrupted jobs with the same request ID and body. A changed body conflicts. Scans pin one commit and never run repository code. Partial coverage stays visible. The tracking artifact adds the exact adopted goal and changes only reviewed, scanned source files. Later edits to an already committed v2 goal are not supported by this first path.

The v2 outcome counts logged events with typed success and failure values. It does not count people or prove answer quality. Native retained events and independently fetched PostHog aggregates keep separate source contracts. Missing environment, release tags or sufficient sample keeps the rate unknown. PostHog cannot reproduce a historical ingestion cutoff, so cross-window comparisons remain inconclusive. Railway proof requires the latest successful deployment to match the reviewed commit and configured project, service and environment. Deployment, fresh event signal and product benefit are separate stages. Before/after is observational.

CLI and local MCP expose the same receipts. Provider credentials and owner policy grants are not MCP tool inputs. Product analytics

GET/POST   /api/{funnels|segments|retention}?project=ID
POST       /api/{funnels|segments|retention}/analyze?project=ID
PUT/DELETE /api/{funnels|segments|retention}/{id}?project=ID&revision=LAST_READ
POST       /api/catalog?project=ID
POST       /api/catalog/describe?project=ID

Readers and analytics-purpose read keys can list/analyze. Editors save descriptions and definitions. Updates/deletes require the last-read revision. Oversized analyses fail explicitly at 200,000 events; definitions are limited to 100 per kind/project. No raw member IDs are returned.

Funnels count identified entrants once per step in strict timestamp order within the conversion and observation windows. Typed event filters support equality or one-of arrays. Entry breakdowns use each identity’s first qualifying entry, with at most 20 disjoint groups. A unique-cohort rate is not an average of daily rates. Nonconverters with an open conversion window are labeled.

Segments use active identities in the selected window and current traits. They cannot find every inactive signup or reconstruct historic profiles. Retention uses first qualifying start inside the selected window, day/week calendar periods, named timezones, exact-period or on-or-after return rules. Unfinished cells are unavailable, never zero; each mature cell has its own eligible denominator. This is not automatic Amplitude parity.

The data dictionary returns observed names/types/presence, no property values. Owners/editors supply meanings and units; they are current metadata even for fixed event windows and are untrusted data.

Owner + Codex request audit

POST /api/audit/catalog?project=ID
POST /api/audit/review?project=ID
POST /api/audit/trace?project=ID
PUT  /api/audit/evidence/{UUIDv4}?project=ID

Start a review with {} or {"limit":60,"expected_environment":"production"}. Discover meanings first. Reuse the exact returned query for a trace and add its opaque request reference. The audit distinguishes stored events, linked requests, latest business attempts, declared eligibility and independent comparable pairs. False means not required; absent/null means unknown. Missing means unobserved in this bounded window, not proof a step was skipped. Expected-environment stage latency has sample counts and nearest-rank p50/p95.

Producers must emit the explicit properties.afterspan_audit contract. Fresh UUIDv4 refs link requests/attempts/releases; redacted/missing refs never join. Independent shadow generation, matching canonical input/decision semantics and one release are required for agreement. Digests are project-keyed HMACs compared only on the server. Agreement and reported success cannot establish semantic correctness, resulting business state, overall safety or readiness.

Editors may attach immutable sanitized historical PostHog aggregate attestations with stable UUIDs. They retain source windows, schema, counts and query hashes. Afterspan does not independently fetch these results; missing cutoff/release coverage stays explicit. Historical counts never silently join the native denominator. No raw chat, reason text or private request identifiers are accepted in the receipt.

Scoped local MCP bridges

The aggregate bridge has 12 read tools, including event_catalog, retention_report and saved_retention. The workspace bridge has 42 tools for scoped team access, optional billing review, product definitions, explicit meanings and historical attestations. Writes need the required role and the human’s request.

The separate audit bridge exposes six scoped tools for catalog, reviews, traces, evaluations and onboarding. An owner runs CLI connect-audit with a private output path; the result gives a nonsecret launcher command for Codex. The launcher reads a mode-600 audit-only receipt. Keys expire and can be revoked. Two fresh Codex CLI clients passed the local synthetic audit using only these three tools; Desktop automatic registration and hosted OAuth MCP remain unproved. All bridges use the official MCP Python SDK over local stdio.

Owners alone grant access; at least one owner remains. Invites require the exact verified email and acceptance. Removing a member revokes personally issued keys; producer keys need explicit rotation. Local mail sends no email; real sender/mailbox delivery is a separate operating check.

Hosted billing is opt-in. Any role reads usage/plans; owners alone inspect billing and create private hosted review links. A person confirms payment/cancellation. Stable UUID retries, signed webhooks and canonical provider state govern paid access. Real Stripe sandbox checkout/upgrade/cancellation were exercised against the local build; live payments and time-advanced renewal remain unverified. No automatic overage charge.

Operating limits

One process, one replica and one persistent SQLite volume. Hourly retention cleanup; backups and restore need separate operational proof. No automatic production rollout, full multi-replica storage, remote OAuth MCP, SSO or MFA. Replay, surveys and richer AI tracing remain planned.
