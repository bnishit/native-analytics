A FEW GOOD QUESTIONS

Less mystery.
By design.

Is the full suite available today?+

The core includes product analytics, linked journeys, versioned goals, searchable traces, metadata-only OTLP/HTTP, reviewed datasets and experiments, selected debugging and collection health. API, CLI and scoped MCP share the supported engines. Goals select each check’s version, timing and evidence requirement, plus completion, delivery or producer-reported usefulness milestones. Replay, surveys, annotation queues, enterprise SSO/MFA and a prompt registry are not included. A local check or provider receipt does not prove a useful customer outcome. Deployment and operating limits remain explicit.

Does Afterspan need my users' private content?+

Prompts and responses are off by default. Owners can enable bounded selected debug snapshots with review, redaction, encryption, expiry and separate editor access. Redaction is best effort; metadata-only tracing remains available. Optional opaque account subjects link traces to account erasure without appearing in trace views. Raw account IDs and extra native attributes are rejected. Erasure blocks later replay of the same trace; old backups require separate erasure reconciliation. This public page is a labelled historical preview and collects no private prompts.

Can my coding agent change the product?+

Scoped tools let an agent inspect evidence and, with separately approved editor permissions, manage goals, reviewed experiments and saved definitions. Existing grants never expand automatically. Owners can adopt exact GitHub/Railway deployment evidence. Repository changes and cloud releases use their own reviewed permissions and exact release evidence; an analytics OAuth grant cannot deploy code. Before/after observations do not establish that a release caused an improvement.

What about bots, desktop tools and CLIs?+

Installable Python and Node helpers support application tasks and trusted context handoffs. Live synthetic tests cover a Slack agent and a signed-in library Q&A: nested steps, model timing, reported token counts and declared source checks. A read-only Tracker evaluation also compares real model decisions on fixed synthetic catalog cases. These tests do not establish normal-user benefit or general factual answer quality. Explicit model observers cover Chat Completions, Responses and Messages formats without collecting content. Responses and Messages have synthetic package checks and two live gateway-format probes. A direct native OpenAI Responses test also retained reported usage and first-output timing in Traces, with cost and business outcome unknown. Native Anthropic and broad framework coverage remain unproved. The Node observer can read one normalized AI SDK model step’s token counts without copying raw usage or adding a framework dependency. Adapters that fill missing details with zero need their preserved protocol usage instead. Missing counts and exact cost stay unknown; this is explicit instrumentation, not automatic coverage of every model call. Metadata-only OTLP/HTTP supports other instrumented runtimes. The Slack adapter reuses one request stream. Node helpers can keep streamed request timings open until completion, failure or cancellation; this does not prove delivery to a person. Python has a durable outbox; Node uses a bounded memory queue. Instrumentation and collection gaps remain visible rather than implying automatic coverage of every app.
